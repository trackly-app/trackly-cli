# Finish Apply setup

Treat setup as a guided conversation. Read the current profile and schema through trackly_get_profile_onboarding or equivalent profile reads. Derive next steps from authoritative completeness and saved states. Explain Apply capability separately from profile completion. Incomplete setup is not a rollout failure, and absent answers or an absent upload do not resolve by waiting.

1. Check availability before interpreting saved state. If profile or schema is unavailable, report the failed check and a concrete next action without asking the user to repeat saved setup.
2. Explain remaining requirements in the user's language. Ask only canonical questions that remain unknown or need confirmation. Preserve answered, declined and intentionally blank fields. Save only user-confirmed facts and scopes using the current revision, then refetch the profile. Education updates replace the entire saved list. Never send a partial education list. Guide missing education through https://usetrackly.app/profile with the same account to edit only missing fields and preserve existing records, then refetch the profile after they save. Never invent missing facts or claim an unsaved conversational answer was stored.
3. Treat documents.default_resume as a file requirement. If no stored default resume is available, give https://usetrackly.app/profile and explain how to sign in with the same Trackly account, upload the original resume and select Set Default if needed. A PDF attached to a conversation or permission to use it does not store the file in Trackly. Do not invent an incoming chat-file import operation. After the user confirms the upload, refetch the profile and verify it returns a stored default resume. Employer attachment is a later step.
4. When requirements are complete but the profile is unconfirmed, ask the user to review and explicitly confirm it. Save confirmProfile: true with the current expectedRevision through trackly_update_application_profile only after confirmation. Refetch the profile and verify confirmedAt is present, a stored default resume exists and no missing requirements remain before continuing.
5. Name any failed operation and the next concrete action. Avoid repeated polling. Capability disablement, incomplete setup, unavailable checks and a host without a controlled browser are distinct blockers. Profile readiness does not prove browser capability. Never submit an application or infer submission from setup completion.
