# Finish Apply setup on Claude

Treat setup as a guided conversation driven by typed state. `trackly_get_profile_onboarding` is the setup read: `nextAction` is `upload_resume_in_trackly`, `complete_missing_requirements`, `review_and_confirm_profile` or `none`. Use its `questions` entries (`key`, `label`, `inputType`, `sensitivity` and `options` with `value` and `label`) to ask for a missing answer. Never guess a stored option value from its label. Explain Apply availability separately from profile completion: incomplete setup is not a disabled feature, and missing answers or a missing upload do not resolve by waiting.

1. If a setup read fails, saved state is unknown. Name the failed tool and its `code`, and do not ask the user to repeat saved setup.
2. Read saved answers with `trackly_get_application_profile` before asking anything. An answer it lists with `status: answered`, `declined` or `blank` is saved: never ask for it again. Equal-opportunity and identity-document keys report only that status (`withheld: special_category`). Other sensitive answers show `withheld: sensitive` unless the user asks to see them and the connection allows sensitive reads (`includeSensitive: true`).
3. Explain the remaining requirements in the user's language and ask only for the listed missing keys. Save only user-confirmed facts and scopes with `trackly_save_application_answers`, passing the current `profileRevision` as `expectedRevision`. A `profile_revision_conflict` error means the profile changed: read setup again and retry once with the new revision. After saving, read setup again. Never invent a fact or claim an unsaved answer was stored.
4. `upload_resume_in_trackly`: the default resume is a file stored in Trackly. Send the user to https://usetrackly.app/profile, signed in with the same account they connected to Claude, to upload the original resume and select it as default. A file attached to this Claude chat is not stored in Trackly, and these tools cannot import one. After the user confirms the upload, read setup again and check that `defaultResumeAvailable` is true.

   If the user already uploaded it but a fresh read still reports no default resume, help them check that the website account is the one they chose when connecting Trackly in Claude, and that the file is selected as default and stays selected after reopening the profile. The tools do not show which account is signed in; a name or an editable profile email is not proof. Offer the normal reconnect flow only with the user's approval, then read setup once more. If it still reports no default, say exactly which check is unresolved and point to https://usetrackly.app/support. Do not claim an account mismatch, outage or successful storage without evidence.
5. Education and work history are edited on the website. When `profileEditUrl` is set, send the user there with the same account to add only what is missing; do not send a partial education list through the save tool, because an education save replaces the whole list. Read setup again after they save.
6. `review_and_confirm_profile`: requirements are complete but the profile is unconfirmed. Ask the user to review it (the profile read shows the saved answers) and explicitly confirm. Only then save `confirmProfile: true` at the current revision, and read setup again until `nextAction` is `none`.
7. Name any failed operation and the next concrete action. Avoid repeated polling. A disabled feature, incomplete setup, an unavailable read and a missing Claude in Chrome connection are different blockers. Setup completion never means an application was submitted.
