# Finish Apply setup

Treat setup as a guided conversation. Follow onboarding.nextAction and guidance from current readiness when supplied. On older responses, derive these steps from available profile data. Explain Apply capability separately from profile completion. Incomplete setup is not a rollout failure, and missing answers or an absent upload do not resolve by waiting.

1. Check availability before interpreting a section. An unavailable profile or schema means saved state is unknown. Report the failed check and a concrete next action without asking the user to repeat saved setup.
2. Explain remaining requirements in the user's language. Ask only canonical questions that remain unknown or need confirmation. Preserve answered, declined and intentionally blank fields. Save only user-confirmed facts and scopes using the current revision, then refetch readiness. Never invent missing facts or claim an unsaved conversational answer was stored.
3. Treat documents.default_resume as a file requirement. If no stored default resume is available, give https://usetrackly.app/profile and explain how to sign in with the same account connected to the plugin, upload the original resume and select Set Default if needed. A PDF attached to ChatGPT, or permission to use it, does not store the file in Trackly. These tools have no incoming chat-file import operation. After the user confirms the upload, refetch readiness and verify defaultResumeAvailable is true. Employer attachment is a later step.
4. Education updates replace the entire list. Value-free readiness does not expose the saved entries. When education is missing, follow profileEditUrl or use https://usetrackly.app/profile with the same account to edit only missing fields and preserve existing records. Do not send a partial education list or ask the user to repeat saved entries; refetch readiness after they save.
5. When requirements are complete but the profile is unconfirmed, ask the user to review and explicitly confirm it. Save confirmProfile: true with the current expectedRevision through trackly_save_application_answers only after confirmation. Refetch readiness and verify profile.confirmed, a stored default resume and no missing requirements before continuing.
6. Name any failed operation and the next concrete action. Avoid repeated polling. Capability disablement, incomplete setup, unavailable checks and a host without a controlled browser are distinct blockers. Profile readiness does not prove browser capability. Never submit an application or infer submission from setup completion.
